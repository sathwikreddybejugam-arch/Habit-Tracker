# Habit Tracker

A Flutter habit tracker with Firebase email/password authentication. Users must
sign in or create an account before opening the habit dashboard.

## What's included

- Email/password sign-up and sign-in
- Firebase auth-state gate (restores the signed-in session)
- Password reset email
- Sign out
- Firebase Authentication errors translated into readable messages
- Existing habit list and statistics UI

## 1. Create the Firebase project

1. Open the [Firebase Console](https://console.firebase.google.com/) and create a project.
2. In **Build → Authentication → Sign-in method**, enable **Email/Password**.
3. Register the app platforms you plan to run. Use the Android application ID and iOS bundle ID generated by the Flutter project.

## 2. Generate the missing Flutter platform folders

This repository intentionally contains Dart source only; it does not currently
include `android/`, `ios/`, or `web/`.

From the repository root, run:

```bash
flutter create .
```

Keep the existing `lib/` folder and review any generated changes before
committing them.

## 3. Connect Flutter to Firebase

Install the FlutterFire CLI (and make sure the Firebase CLI is installed and
logged in):

```bash
dart pub global activate flutterfire_cli
firebase login
flutterfire configure
```

Select the Firebase project and the platforms you generated. The command
creates `lib/firebase_options.dart`, which is imported by `lib/main.dart`.
Do not hand-write this file: generate it for your own Firebase project.

Then install the Dart dependencies:

```bash
flutter pub get
```

## 4. Run the app

```bash
flutter run
```

Create an account from the first screen, sign out from the account menu, and
sign back in to verify that Firebase restores the authenticated session.

## Authentication flow

1. `main.dart` initializes Firebase with the generated platform options.
2. `AuthGate` listens to `FirebaseAuth.authStateChanges()`.
3. Signed-out users see `AuthScreen`; signed-in users see `HabitHomePage`.
4. `AuthService` wraps Firebase email/password sign-in, sign-up, password
   reset, and sign-out operations.
5. Firebase Authentication manages the credential exchange and persisted
   session. The app does not manually save passwords or Firebase ID tokens.

## Credential and token handling

- Passwords are submitted to Firebase Authentication over the Firebase SDK;
  this app does not write passwords to local files or a database.
- Firebase SDK manages the signed-in session and refreshes ID tokens. Do not
  copy ID tokens into preferences, source code, or Git.
- Never commit Firebase Admin SDK service-account JSON files or private keys.
- The generated `firebase_options.dart` contains Firebase app configuration,
  not an Admin SDK private key. Generate it for your own Firebase project.

## Current limitation: habit data is not cloud-synced

Authentication now gates access to the dashboard, but habits are still held in
an in-memory list. They are not yet saved to Firestore or associated with a
Firebase user, and they will be lost when the app process restarts. The next
backend step is to add Cloud Firestore and store each user's habits under their
Firebase UID, with Firestore Security Rules enforcing per-user access.
